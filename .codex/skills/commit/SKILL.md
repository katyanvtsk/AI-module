---
name: commit
description: Создать локальный Git-коммит из staged-изменений по явному запросу пользователя.
---

1. Посмотри `git status --short` и `git diff --cached`.
2. Если staged-изменений нет, попроси пользователя выбрать файлы для коммита. Если пользователь уже указал файлы, добавь только их. Не добавляй все изменения автоматически.
3. Проверь staged-дифф на случайно добавленные секреты и посторонние файлы. При обнаружении проблемы сообщи о ней и не создавай коммит до её разрешения. Не выводи значения секретов.
4. Запусти `npm.cmd run check` и `npm.cmd run build`. Если проверки упали, не создавай коммит; сообщи причину. Проверки выполняются для рабочего дерева: при наличии unstaged-изменений не утверждай, что проверен только staged-снимок.
5. Придумай короткое сообщение в повелительном наклонении, описывающее staged-изменения. Используй сообщение пользователя, если оно задано.
6. Создай локальный коммит через `git commit`. Явный вызов скилла уже является поручением создать коммит; дополнительное подтверждение сообщения не требуется. Соблюдай системные запросы разрешений.
7. Покажи хеш, сообщение коммита, результаты проверок и итоговый `git status --short`.

Не выполняй `push` и не используй `--amend` без отдельного запроса. Не обходи hooks через `--no-verify` и не удаляй изменения пользователя.
