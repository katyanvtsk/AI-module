# Руководство по работе с репозиторием

## Структура проекта и организация модулей

Проект — доска задач на React 19, TypeScript и Vite с хранением данных в браузере.

- `src/main.tsx` запускает приложение; `src/app/` содержит его оболочку и глобальные стили.
- `src/features/tasks/` объединяет компоненты задач, предметные типы в `model/` и демонстрационные данные в `data/`.
- `src/components/` содержит доску и устаревшие компоненты карточек и статистики.
- `src/services/` определяет интерфейс `TaskRepository` и его реализацию на localStorage.
- Тесты размещаются рядом с проверяемыми модулями; `src/test/setup.ts` настраивает очистку после тестов и проверки DOM.
- Стили компонентов находятся рядом в файлах `*.module.css`. Отдельного каталога статических ресурсов пока нет. Результат сборки записывается в `dist/`.

# Работа с задачами

- Для отображения задач и вычисляемых показателей используй список,
  уже загруженный в `TaskBoard`; передавай его компонентам через props.
  Не читай `localStorage` напрямую в UI-компонентах. Для загрузки
  и изменения задач используй `TaskRepository`.

# Готовность

- Перед сдачей запусти `npm run check` и `npm run build`.

## Стиль кода и правила именования

Соблюдайте существующее оформление: отступы в два пробела, одинарные кавычки в TypeScript, отсутствие точек с запятой после инструкций и завершающие запятые в многострочных структурах. Используйте PascalCase для React-компонентов и их файлов, camelCase для функций и переменных, `import type` для импорта типов. Называйте файлы CSS Modules по соответствующим компонентам, например `TaskForm.module.css`.

ESLint включает правила TypeScript, React Hooks и React Refresh; отдельный форматтер не настроен. При изменении интерфейса сохраняйте русский язык и подписи для вспомогательных технологий.

## Правила тестирования

Используйте Vitest с jsdom, React Testing Library, user-event и jest-dom. Называйте тесты сервисов `*.test.ts`, а интерфейса — `*.test.tsx`. Предпочитайте поиск элементов по ролям и подписям и имитацию действий пользователя. Изолируйте интерфейс с помощью тестовых замен `TaskRepository`; в тестах хранения задавайте фиксированные идентификаторы и время. Проверяйте изменённое поведение и соответствующие сценарии ошибок. Минимальный порог покрытия не настроен.

## Коммиты и пул-реквесты

История Git пока содержит только `Initial commit`, поэтому устоявшегося соглашения об именовании коммитов нет. Пишите короткие заголовки в повелительном наклонении, описывающие изменение. Посвящайте каждый пул-реквест одной задаче, описывайте итоговое поведение, добавляйте ссылки на связанные issues и указывайте команды проверки с результатами. Для визуальных изменений прикладывайте скриншоты.
